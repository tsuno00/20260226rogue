# news20260213/AGENTS.md — 実行ルール（唯一の作業指示）

このファイルは、Codex/エージェントの実行ルールのみを定義する。
プロダクトの思想・要件・MVP仕様は `CONCEPT.md` を優先する。

## 最重要：作業フロー（Plan → Approval → Execute）
1. Plan（計画）
   - 目的 / 変更点 / 影響範囲（触るファイル・ディレクトリ）/ リスク / ロールバックを先に提示
2. Approval（承認）
   - ユーザーの明示承認があるまで、コマンド実行・ファイル変更をしない
3. Execute（実行）
   - 承認された範囲だけ実行し、結果（成功/失敗/ログ要点）を短く報告

## コマンド実行ルール（勝手に実行しない）
- ユーザー承認なしにコマンドを実行しない
- 提案コマンドはそのままコピペ可能な形で提示する
- 1回の承認で通すコマンドは、できるだけ少なく（2〜5個程度）まとめる

## 破壊的・高リスク操作は必ず再承認
以下は実行直前に再確認する。
- `rm -rf` / 広範囲削除 / 大量上書き / 一括置換 / 権限・所有者変更
- `sudo` を伴う操作（`apt`、システム設定変更など）
- ネットワーク利用（`npm install` / `git clone` / `curl` / `wget` 等）
- `/home` 外へのアクセス、`/mnt/c` 利用

## 作業範囲（WSL）
- すべて `/home/shingo/code/{projectname}` 配下で完結させる
- `{projectname}` は現在作業中のリポジトリ名を指す
- `/mnt/c` は原則禁止。必要時は実行直前に再承認を取る
- 生成物（例：`dist/`）はプロジェクト配下に閉じ込める

## 秘密情報の禁止
- APIキー/トークン/パスワード等をファイルに直書きしない
- `.env` を使う場合は必ず `.gitignore` し、README/ログ/サンプルにも載せない

## 最小の成功（Minimal Success）優先
- まずは最小構成で build/test が通る状態を優先する
- 新規依存追加は最小限（理由と影響を説明して承認を取る）
- 変更は小さく、常に動作確認可能な状態を維持する

## 未解決事項の管理（必須）
- リリースまでに決定が必要な未解決事項が出た場合、必ず `DECISIONS.md` に追加する
- 実装時は `DECISIONS.md` の暫定運用に従い、独断で仕様確定しない
